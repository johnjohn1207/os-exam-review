考點五：死結四大必要條件與破壞預防機制矩陣（Four Necessary Conditions & Prevention Matrix） 名詞解釋必背
必要條件定理： 死結發生當且僅當以下四項條件同時成立。死結預防（Deadlock Prevention）只要成功打破其中任何一項，即可保證系統絕不死結。
必要條件名稱 條件精準定義 破壞手段與實作機制 實務可行性與系統代價
互斥
(Mutual Exclusion)		 至少有一項資源必須處於非共用模式，一次僅能由一個行程持有；其他行程請求時必須等待。 將資源改為完全可共用模式（例如唯讀檔案 Read-only Files）。 極難破壞。多數硬體設備（如印表機、磁帶機）本質上具有不可共用性，無法同時被多個行程寫入。
持有並等待
(Hold and Wait)		 行程至少持有一項資源，同時又在等待取得其他已被其他行程佔用的資源。 1. 協定一：行程在開始執行前，必須一次性申請並獲配全部所需資源。
2. 協定二：行程僅在未持有任何資源時，才可提出新的資源請求。		 可行但代價高昂。會大幅降低資源利用率（未用資源被長期鎖定），且需要多種資源的大型行程極易面臨飢餓（Starvation）。
不可搶佔
(No Preemption)		 資源不能被系統強制剝奪，只能由持有該資源的行程在完成工作後自願釋放。 若持有資源的行程申請新資源無法立即獲得，系統強制搶佔並釋放其已佔有的所有舊資源；等所有資源皆可獲得時再重啟。 僅適用於狀態容易保存與還原的資源（如 CPU 暫存器與主記憶體）；對印表機、資料庫鎖定等難以任意搶佔。
循環等待
(Circular Wait)		 存在等待行程鏈 $\{P_0, P_1, \dots, P_n\}$，其中 $P_0$ 等待 $P_1$ 持有之資源……$P_n$ 等待 $P_0$ 持有之資源，形成封閉環狀。 建立全域總排序編號（Total Ordering）：對所有資源定義一對一函數 $F: R \to \mathbb{N}$，規定行程必須嚴格依資源編號之遞增順序提出申請。 最常用且高度可行的預防手段。數學上可完全防止環路形成，但程式撰寫限制較大，且編號排序設計必須符合實際執行相依性。

【大題一】銀行家演算法綜合分析題（教材範例 1）

系統中有 5 個行程（$P_0 \sim P_4$）與 3 種資源類型：$A$（10 個實例）、$B$（5 個實例）、$C$（7 個實例）。時間點 $T_0$ 的資源配置狀態如下：

行程 已分配資源 Allocation (A B C) 最大需求量 Max (A B C) 系統可用資源 Available (A B C) 尚需資源 Need = Max - Allocation
P0 0 1 0 7 5 3 Available = (3, 3, 2)
A: 10 - 7 = 3
B: 5 - 2 = 3
C: 7 - 5 = 2 		(7, 5, 3) - (0, 1, 0) = (7, 4, 3)
P1 2 0 0 3 2 2 (3, 2, 2) - (2, 0, 0) = (1, 2, 2)
P2 3 0 2 9 0 2 (9, 0, 2) - (3, 0, 2) = (6, 0, 0)
P3 2 1 1 2 2 2 (2, 2, 2) - (2, 1, 1) = (0, 1, 1)
P4 0 0 2 4 3 3 (4, 3, 3) - (0, 0, 2) = (4, 3, 1)

推導步驟一：執行安全演算法（Work = Available = (3, 3, 2)）

  1. 檢查 $P_1$：$Need_1(1, 2, 2) \le Work(3, 3, 2)$ 成立 $\implies Work = Work + Allocation_1 = (3, 3, 2) + (2, 0, 0) = \mathbf{(5, 3, 2)}$，$Finish[1] = true$。
  2. 檢查 $P_3$：$Need_3(0, 1, 1) \le Work(5, 3, 2)$ 成立 $\implies Work = Work + Allocation_3 = (5, 3, 2) + (2, 1, 1) = \mathbf{(7, 4, 3)}$，$Finish[3] = true$。
  3. 檢查 $P_4$：$Need_4(4, 3, 1) \le Work(7, 4, 3)$ 成立 $\implies Work = Work + Allocation_4 = (7, 4, 3) + (0, 0, 2) = \mathbf{(7, 4, 5)}$，$Finish[4] = true$。
  4. 檢查 $P_2$：$Need_2(6, 0, 0) \le Work(7, 4, 5)$ 成立 $\implies Work = Work + Allocation_2 = (7, 4, 5) + (3, 0, 2) = \mathbf{(10, 4, 7)}$，$Finish[2] = true$。
  5. 檢查 $P_0$：$Need_0(7, 4, 3) \le Work(10, 4, 7)$ 成立 $\implies Work = Work + Allocation_0 = (10, 4, 7) + (0, 1, 0) = \mathbf{(10, 5, 7)}$，$Finish[0] = true$。

結論：所有行程之 Finish 皆為 true，系統處於安全狀態，合法安全序列為 $\langle P_1, P_3, P_4, P_2, P_0 \rangle$。

推導步驟二：動態資源請求評估

1. 行程 $P_1$ 提出請求 $Request_1 = (1, 0, 2)$：

  • 檢查 1：$Request_1(1, 0, 2) \le Need_1(1, 2, 2)$（符合）。
  • 檢查 2：$Request_1(1, 0, 2) \le Available(3, 3, 2)$（符合）。
  • 假裝分配更新：$Available = (3, 3, 2) - (1, 0, 2) = \mathbf{(2, 3, 0)}$；$Allocation_1 = (3, 0, 2)$；$Need_1 = (0, 2, 0)$。
  • 執行安全演算法：以 $Work = (2, 3, 0)$ 出發，可依序執行 $P_1 \to P_3 \to P_4 \to P_0 \to P_2$，維持安全序列 $\langle P_1, P_3, P_4, P_0, P_2 \rangle$。
  • 結論：假裝分配後系統仍為安全狀態，可以立即批准分配！

2. 承上，$P_1$ 獲批後（$Available = (2, 3, 0)$）之後續請求：

  • $P_4$ 提出 $Request_4 = (3, 3, 0)$： 資源 $A$ 需要 3 個，但目前 $Available$ 僅剩 2 個（$3 > 2$），可用資源不足，無法批准，行程 $P_4$ 必須等待。
  • $P_0$ 提出 $Request_0 = (0, 2, 0)$： $Request_0 \le Need_0(7, 4, 3)$ 且 $Request_0 \le Available(2, 3, 0)$，經安全演算法驗證可維持安全狀態，可以批准分配。

【大題二】多重實例死結偵測演算法（教材範例 2）

系統中有 5 個行程（$P_0 \sim P_4$）與 3 種資源（$A = 7, B = 2, C = 6$）。在時間點 $T_0$ 的配置與請求矩陣如下：

行程 已分配 Allocation (A B C) 當前請求 Request (A B C) 系統可用 Available (A B C) 執行判定與資源回收
P0 0 1 0 0 0 0 Available = (0, 0, 0)
A: 7 - 7 = 0
B: 2 - 2 = 0
C: 6 - 6 = 0 		$Request_0(0, 0, 0) \le (0, 0, 0) \implies$ 釋放得 $Work = \mathbf{(0, 1, 0)}$
P1 2 0 0 2 0 2 等待 $Work$ 累積至 $(5, 2, 4)$ 後執行，釋放得 $Work = \mathbf{(7, 2, 4)}$
P2 3 0 3 0 0 0 $Request_2(0, 0, 0) \le (0, 1, 0) \implies$ 釋放得 $Work = \mathbf{(3, 1, 3)}$
P3 2 1 1 1 0 0 $Request_3(1, 0, 0) \le (3, 1, 3) \implies$ 釋放得 $Work = \mathbf{(5, 2, 4)}$
P4 0 0 2 0 0 2 $Request_4(0, 0, 2) \le (7, 2, 4) \implies$ 釋放得 $Work = \mathbf{(7, 2, 6)}$

死結狀態變化分析

1. $T_0$ 時間點偵測結果：

依序執行 $P_0 \to P_2 \to P_3 \to P_1 \to P_4$。所有行程之 $Finish[i] = true$，系統在 $T_0$ 未發生死結，執行完畢序列為 $\langle P_0, P_2, P_3, P_1, P_4 \rangle$。

2. 若行程 $P_2$ 額外提出請求 $Request_2 = (0, 0, 1)$：

  • 此時 $P_2$ 之請求由 $(0, 0, 0)$ 變為 $(0, 0, 1)$。
  • 初始 $Work = (0, 0, 0)$，全系統僅有 $P_0$ 滿足 $Request \le Work$。$P_0$ 完成後釋放資源得 $Work = (0, 1, 0)$。
  • 此時 $Work = (0, 1, 0)$ 無法滿足任何其餘行程：$P_1(2, 0, 2)$、$P_2(0, 0, 1)$、$P_3(1, 0, 0)$、$P_4(0, 0, 2)$ 皆因資源不足無法執行。
  • 結論：系統陷入死結狀態，陷入死結的行程集合為 $\{P_1, P_2, P_3, P_4\}$！

【題型六】阿姆達爾定律（Amdahl's Law）多核心加速比推導
點擊展開【阿姆達爾定律核心公式】
加速比核心公式： $\\text{Speedup} \\le \\frac{1}{S + \\frac{1 - S}{N}}$
- $S$：程式中必須「循序執行（Serial portion）」的比例（$0 \\le S \\le 1$）。
- $1 - S$：可「平行化處理（Parallel portion）」的比例。
- $N$：處理器核心數量（Processing Cores）。
理論加速比極限（$N \\to \\infty$）： $\\lim_{N \\to \\infty} \\text{Speedup} = \\frac{1}{S}$。
